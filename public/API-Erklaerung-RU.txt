TANKTEILER — ПОДРОБНОЕ ОБЪЯСНЕНИЕ ПРОЕКТА И API

Этот документ поможет разобраться, как работает приложение и какие данные
передаются между браузером, сервером и Google Maps. Здесь объяснения подробнее,
чем в тексте выступления.

======================================================================
1. ОБЩАЯ СХЕМА
======================================================================

1) Браузер показывает интерфейс: поля маршрута, карту, данные автомобиля и
   результат расчёта.
2) Автомобиль пользователь добавляет сам. Данные автомобиля сохраняются в
   localStorage — локальном хранилище этого браузера. Они не отправляются на
   сервер и не видны другим посетителям. На другом устройстве этот автомобиль
   не появится; очистка данных сайта может удалить сохранённые машины.
3) Google Maps помогает найти места и построить маршрут.
4) Сервер на Node.js и Express нужен для получения цен на топливо с сайта TCS
   и для передачи настроек Google Maps приложению.
5) Расходы приложение считает само, в браузере. Google Maps не рассчитывает
   стоимость бензина, парковки или платных дорог.

Коротко: Google находит маршрут, браузер хранит машину, приложение считает
расходы, сервер получает цены на топливо.

======================================================================
2. ЧТО ТАКОЕ API
======================================================================

API — это способ, по которому одна программа просит другую выполнить задачу
или передать данные. Например, TankTeiler отправляет Google Maps точки маршрута
и получает расстояние и линию пути.

У запроса обычно есть:
- входные данные: например, адрес, координаты, начало и конец маршрута;
- название операции: например, геокодирование или построение маршрута;
- ответ: найденные координаты, расстояние, точки линии или ошибка.

В этом проекте используются разные сервисы. Важно не смешивать API Google Maps
и внутренние адреса самого приложения вида /api/prices.

======================================================================
3. GOOGLE MAPS JAVASCRIPT API
======================================================================

Это основа интеграции с Google Maps в браузере. Она загружает карту и даёт
JavaScript-коду доступ к функциям Google Maps.

В TankTeiler через эту платформу:
- создаётся и отображается карта;
- подключаются библиотеки для маршрутов, геокодирования и меток;
- показываются точки A, B и остановки;
- отображается линия маршрута.

Браузер загружает API-скрипт с ключом, который сервер получает из настроек
окружения и возвращает через внутренний адрес /api/config. Для браузерного
ключа важно включить ограничения по сайтам (HTTP referrers) и разрешить только
нужные API в Google Cloud.

Ключ виден в браузере, потому что карта работает в браузере. Поэтому его
защищают ограничениями в Google Cloud, а не пытаются считать секретным.

======================================================================
4. GEOCODING — ПОИСК МЕСТА И КООРДИНАТЫ
======================================================================

Геокодирование переводит текстовый адрес в координаты. Например:

  "Zürich, Schweiz" -> широта и долгота

Обратное геокодирование делает обратное: по координатам, выбранным на карте,
может вернуть читаемый адрес.

В приложении пользователь может найти начальную точку, конечную точку или
остановку по тексту. Также можно выбрать точку кликом по карте. Координаты
нужны приложению, чтобы поставить маркер и передать точку в запрос маршрута.

Техническое уточнение: проект использует Geocoder из библиотеки Geocoding
Google Maps JavaScript API. Это функция JavaScript API, а не отдельный
серверный HTTP-запрос, который приложение напрямую формирует.

======================================================================
5. ROUTES API — ПОСТРОЕНИЕ МАРШРУТА
======================================================================

Маршрут рассчитывается вызовом:

  google.maps.routes.Route.computeRoutes(...)

Приложение передаёт:
- origin — начальную точку;
- destination — конечную точку;
- intermediates — промежуточные остановки;
- travelMode: 'DRIVING' — поездка на автомобиле;
- fields — только нужные поля ответа: distanceMeters и path.

distanceMeters — длина маршрута в метрах. Приложение переводит её в
километры для расчёта топлива.

path — список точек линии маршрута. Приложение использует его, чтобы нарисовать
линию на карте.

Routes API не возвращает стоимость бензина или платной дороги. Она рассчитывает
маршрут и возвращает запрошенные данные о нём.

======================================================================
6. ADVANCED MARKERS — МЕТКИ НА КАРТЕ
======================================================================

Библиотека Marker Google Maps JavaScript API используется для меток:
- AdvancedMarkerElement создаёт маркер;
- PinElement задаёт внешний вид маркера;
- draggable-маркеры позволяют пользователю перемещать начало, конец или
  остановку мышью.

Это компоненты Google Maps JavaScript API, а не отдельный сервис маршрутов.
Когда пользователь перемещает маркер, приложение обновляет координаты и
пересчитывает маршрут.

======================================================================
7. РАСЧЁТ ТОПЛИВА, ПАРКОВКИ И ПЛАТНЫХ ДОРОГ
======================================================================

Топливо:
  литры = расстояние в км × расход на 100 км ÷ 100
  стоимость топлива = литры × цена за литр

Для режима «туда и обратно» расстояние для топлива умножается на два.

Общие расходы:
  всего = топливо + парковка + платные дороги
  на человека = всего ÷ количество людей

Платные дороги вводятся как общая сумма за всю поездку. Она не удваивается
автоматически при включении поездки туда и обратно. Парковка также прибавляется
один раз. Доля на человека в интерфейсе округляется вверх до целого франка,
но общая сумма показывается с раппенами.

Пример:
  100 км × 6 л / 100 км = 6 литров
  6 литров × 2 CHF = 12 CHF за топливо
  12 CHF + 9 CHF парковка + 6 CHF платные дороги = 27 CHF
  27 CHF / 3 человека = 9 CHF на человека

При расчёте поездки туда и обратно топливо будет рассчитано на 200 км, но
парковка и платные дороги останутся введёнными суммами на поездку.

======================================================================
8. ЦЕНЫ НА ТОПЛИВО И СЕРВЕР
======================================================================

GET /api/prices — внутренний endpoint TankTeiler. Это не API Google.

Сервер Node.js делает запрос к странице с ценами TCS, извлекает значения для
бензина 95, 98 и дизеля и передаёт их браузеру в JSON. Чтобы не запрашивать
страницу TCS каждый раз, сервер хранит результат в памяти примерно три часа.
Если TCS временно недоступен, приложение возвращает последний сохранённый
результат или запасные значения.

GET /api/config — ещё один внутренний endpoint. Он возвращает браузеру ключ
Google Maps и идентификатор карты из настроек сервера. Это позволяет не
вписывать конфигурацию отдельно в исходный JavaScript.

======================================================================
9. КАК ПРОИСХОДИТ ОДНА ПОЕЗДКА
======================================================================

1) Пользователь вводит адрес или выбирает точку на карте.
2) Геокодер преобразует адрес и координаты, когда это нужно.
3) Браузер отправляет начало, конец и остановки в Route.computeRoutes.
4) Google Routes API возвращает длину маршрута и его точки.
5) TankTeiler рисует маршрут и использует расстояние для оценки топлива.
6) Приложение добавляет парковку и введённую сумму платных дорог.
7) Итог делится на количество пассажиров.
8) Машина остаётся сохранённой только в localStorage этого браузера.

======================================================================
10. ПОЧЕМУ RENDER, А НЕ ТОЛЬКО GITHUB PAGES
======================================================================

GitHub Pages подходит для статических файлов: HTML, CSS, JavaScript и
изображений. Но TankTeiler также запускает сервер Express, который получает
цены TCS и передаёт конфигурацию Google Maps. GitHub Pages не запускает такой
сервер.

Render запускает Node.js-приложение и может отдавать сайт и ответы сервера с
одного адреса. Бесплатный сервер Render может засыпать после бездействия,
поэтому первый запрос после паузы иногда загружается дольше.
